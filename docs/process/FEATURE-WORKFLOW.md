# 功能开发流程

新增功能前阅读根目录 `AGENTS.md`、[文档入口](../README.md)、产品与架构说明，以及相关代码和测试。历史私人规格与批准不随公开仓库提供，不能假定新范围已经得到批准。

1. 明确目标、现状、用户流程、范围与验收标准。
2. 对新业务行为形成规格，保存到 `docs/superpowers/specs/`，记录明确审核结果。
3. 形成文件、接口、数据、风险与验证计划，保存到 `docs/superpowers/plans/`；涉及架构、安全、数据或重要依赖时先明确决策。
4. 在授权范围内实施，保持领域/应用/基础设施边界，运行必要回归。
5. 将需求、实现和验证证据对应，分别报告 PASS、FAIL、PARTIAL 或未运行。用户验收与 Agent 验证分开记录。

这些规格和计划目录在公开快照中没有历史材料；后续新增文档应避免放入私人审批会话、账号、文章或机器路径。小范围低风险修订可以简化记录，涉及真实平台写入时仍需独立限定操作范围。
